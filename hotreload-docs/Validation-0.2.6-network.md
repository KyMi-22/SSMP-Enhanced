# 0.2.6 信号与网络诊断修订（2026-11-05）

仍使用 0.2.6，不递增版本号，不发布至外部平台。唯一需要覆盖的运行文件是 BepInEx/plugins/SSMP/Silksong.CoopAssist.dll；各端退出游戏后覆盖并重启一次。实际游戏目录与存档未安装或修改。

## 改动

- 接管 SSMP 左上角 Ping 显示，停止原先每帧数字转字符串和文字赋值。用原图标位置下的四个 UI Image 显示信号，最多每半秒刷新一次；原显示开关、菜单隐藏、断线隐藏仍由 SSMP 的原组件组控制。支持 UI 先创建或后创建，两种顺序均只附加一次。
- 四格绿色、三格黄色、两格橙色、一格红色；无有效连接为灰色。Ping 的分级界线为 80/160/300 毫秒；同场景队友的近期位置更新中断达到 70/150/350 毫秒也会降低等级，峰值保留三秒。改善稳定两秒后才升格。跨场景队友不参与位置中断判定。
- 增加按玩家、方向区分的 [PeerFlow]，每约 15 秒输出 UTC 本机记录时间、场景、窗口长度、调用频率、最大间隔、长间隔计数和本地处理等待。内存有上限；玩家离开及断线时清理身份与序号。热点使用缓存委托，不对每次更新做反射或枚举值装箱。
- 保留旧版皮肤/UI/中文名字修复和人物平滑。本次没有基于尚未分清的网络原因提高采样率或改变人物位置预测，没有改 SSMP.dll 或线上消息格式。

## 日志含义

| stage | 所在边界 |
|---|---|
| Sample | 本地位置写入待发送包；不是已经发到网线的次数 |
| ClientSend | 客户端调用传输层发送；包含位置以外的数据与分片 |
| ServerSend | 房主向 peer 指定的客户端调用传输层发送；同样包含非位置数据 |
| HostReceive | 房主已解码的位置数据进入包分发器 |
| HostApply | 房主开始处理该玩家位置，等待从 HostReceive 计时 |
| ClientReceive | 客户端已解码的位置数据进入包分发器 |
| ClientApply | 客户端开始处理该玩家位置；等待使用原 [Playback] 的解码时间 |

older/duplicate 只观察相同方向、相同玩家位置数据所携带的包序号。不把缺少的位置序号计为丢包，因为中间的包可能承载其他数据。记录不改变接收顺序或过滤行为。localWait/sendCall 为等待/发送调用耗时的平均值和最大值，均为本机计时，不是网络 RTT。ServerSend 在映射未建立的极短启动阶段可能标为 unmapped。
