# 0.2.9 合作测试版：同步、传送与个人复活点

日期：2026-11-08。底层固定 SSMP 0.4.142；所有端必须安装本次同一 DLL。GameTested=false，MultiplayerTested=false。

## 同步原则与修复

每次加入默认在加载前同步房主世界进度及物品、材料、装备、消耗资源，数量按房主覆盖；只有念珠余额、暂存念珠、念珠串保持个人独立。覆盖是用户明确要求，游玩中拾取仍沿用 SSMP 处理，并非每帧共用背包。碎石平台各端独立。

补齐 visitedMosstown、visitedBoneBottom、visitedMossCave、pilbyMosstownConvo：原先不在 SSMP 生成表里，现在自动入房和原生实时剧情通道共用同一补充列表。苔莓数量与 mosstownAspidBerryCollected、druidMossBerriesSold、mossBerryValueList 同取一份房主快照。原生表内可识别的世界/重要物品来源也按该快照覆盖，避免“数量回到房主、来源仍是客机并集”。未分类的个人来源、念珠拾取和临时平台保留原生分类；没有按名字猜测全图对象，没有替换整个 sceneData。这并不证明全地图事件已逐个验收。

## 手动一键同步与保存

客机坐长椅后，在 F7 或“选项 → 模组 → 联机体验”点击“按房主一键同步”，关闭设置并留在长椅上。流程：获取新房主快照 → 保存当前个人状态 → 确认备份成功 → 调用与自动加入相同的合并策略 → 写入同步存档 → 通过游戏 LoadGameFromUI 路线重载。长椅用于稳定切换整份进度和刷新运行对象，不在角色运动中直接替换 PlayerData。

请求绑定随机标记及槽位，客户端不能上传自己的快照充当房主。队列有界，快照上限 4 MiB，30 秒未完成接收或等待操作则取消；已开始的原生异步写入不强制中断。快照使用 SSMP 可靠大包；小存档用 JSON 尾部空格补到大包门槛，避免 65535 字节字符串限制。房主加载/倒地/保存或未校验时拒绝，按成员间隔 5 秒限流。主线程才操作 Unity 和存档。

手动覆盖前额外备份位于存档同目录 CoopAssist-Backups，备份失败不覆盖。入房恢复正常操作后自动保存，之后约每 30 秒在安全状态保存，离线通知时尽量补存。单路写入，失败 5 秒后重试；不与原生保存重叠。强制结束、崩溃或断电时最后一个周期内的变化仍可能未落盘。

## 传送

客机日志连续三次传送均等待 8 秒超时。SSMP NetServer.GetNetworkReceiver 第二次获取已有接收器时，局部 networkReceiver 为空，却仍写回消息解析配置。旧插件调用两次；现在统一获取一次，注册颜色、传送和手动同步。

从长椅存档加载时 EntryGateName 可能是 RestBench，它不是普通转场入口。新增在 SceneTeleportMap 中查找真实入口，入房集合、传送、复活点共用；最终落点依然验证本机地形和伤害区。只有一位在线队友时 F6 自动选中，多人仍需明确选择。

## 手动复活点

存活并离开长椅后，在固定安全地面打开 F7 或联机体验设置，点“设定当前安全位置为复活点”。每个账号存档槽独立保存；“清除自定义复活点”恢复默认，清空槽位也清除对应记录。没有新增默认快捷键。

成茧按原返回键（默认 F5，手柄绑定保留）：先完成 SSMP/游戏正常死亡恢复，再自动通过普通入口返回设定场景并落到重验坐标。**这是恢复后的自动返回，仍可能短暂加载长椅，不是绕过死亡直接复活。**被队友救起不触发；不强制解锁控制、不重写死亡协程、不额外复活钢魂死亡档。

移动平台、危险地面或入口不明时拒绝设置；返回时地形变化/危险则保留正常长椅位置或目标场景入口。最多等待 60 秒，换槽或离线即取消。没有完成 Boss 封门自动集合，不保证封门场景的跨图返回。

## 性能与代码组织

- 修复消息初始化，未以延长超时掩盖问题。
- 禁用换图后遍历全体 FSM/状态/动作并逐对象打印的 LogStoryReadersNow 调试转储，保留慢帧和网络阶段诊断。
- 安全检查缓存人物 Collider，改用 Unity 当前无分配重叠查询。
- F7 增加整页滚动和固定关闭按钮。
- HostResourceSync / HostWorldSync 是纯策略；NativeSaveBridge 集中私有绑定；HostSnapshotMessage 负责封包；CheckpointSchedule / ReturnJourney 是独立可测状态逻辑；落点操作统一到 PlaceHeroAt。

客机日志信号采样 Ping 中位数 31 ms、P95 为 68 ms，已单独记录的本机慢帧最高 637 ms；房主记录的本机慢帧最高 385 ms。信号采样是变化时记录，不是等间隔全量 RTT 分布。可确认网络抖动与本机长帧同时存在。本次没有实机帧耗时/网络延迟对照，不保证三人卡顿和高延迟全部消失；实体初始化、GC、资源加载仍需继续实测。

## 验证与边界

构建和完整 tools/Test.ps1 回归通过。新增 733 项：保存串行、重试、旧回调、跨槽取消；死亡恢复前不移动；大/小快照编码和真实 SSMP ChunkAddonPacketBuilder；苔栖镇标记、苔莓来源与数量、念珠保留、世界记录幂等。静态检查服务端仅获取一次接收器及新增原生目标。既有大厅、传送、资源、人物平滑、字体、换肤、信号、收包所有权回归保留。

检查包括纯逻辑、真实封包执行和静态签名，**没有执行 Unity、真实存档异步回调、双人/三人网络或 GPU**。必须实机确认：同一包重连苔栖镇；物品/念珠分别核对；长椅一键同步重载；同图/跨图传送；设点后 F5、队友救援、清除点、地形变化和换槽。

## 已丢失苔莓的补偿

本机第二槽只读检查：苔莓 1、售出计数 0、愿望未完成。按用户报告“少了一个”，另生成仅把该物品数量 1 → 2 的私人修复副本及原档备份，没有直接安装或重置剧情。该信息不能独立证明漏发原因。私人副本不进入安装包；通用 tools/Repair-Mossberry.ps1 只写新目录并拒绝覆盖。
